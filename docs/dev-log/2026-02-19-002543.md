## Key Decisions

- **Undo stack is session-only, not persisted**: Undo history lives in Zustand memory and resets on app restart. Persisting undo across sessions was considered out of scope for this iteration.
- **System tag removal sets value to null, not delete**: Deleting a system tag entirely would break the invariant that every object always has media_type and file_extension entries. Setting to null preserves structure while communicating "no value known."
- **Null system tags always rendered**: Rather than hiding null-valued system tags, they display as "(empty)" so the user can see the slot exists and understand why it has no value.
- **Undo restores full object state including user tags**: When undoing an object deletion, the restore operation replays both the object record and its tag assignments so the object returns to its exact prior state.

## Critical Architectural Note: Tag Definitions vs. Tag Assignments

This session surfaced and explicitly verified a subtle but load-bearing invariant in the data model:

**Tag definitions are shared. Tag assignments are per-object.**

A tag definition (label, color, type, value) is a single record referenced by many objects. When a user appears to "edit a tag" on one object, the correct behavior is:

1. Create a new tag definition with the updated value
2. Assign the new definition to the object
3. Unassign the old definition from the object

The old definition is left intact because other objects may still reference it. Modifying the definition in place would silently change the tag's meaning for every object that uses it.

The current implementation in `TagAssignmentSection.jsx` and `db-handlers.js` follows this pattern correctly. This is easy to break when adding new tag-editing paths - any future work touching tag mutation must treat definitions as immutable shared records and create new definitions rather than updating existing ones.

## Technical Notes

- Undo store pattern: each action pushed to the stack is a plain object with a `type` field and enough data to fully reverse the operation (snapshot of deleted record, previous tag assignment, etc.)
- System tags (media_type, file_extension) are distinguished from user tags in the data model; their removal path is intentionally different and must stay that way
- SQL null-safety: queries that filter or display tag values must use `IS NOT NULL` guards or coalesce equivalents to avoid runtime errors on null-valued system tags
