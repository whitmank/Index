## Index v0.4 — Code Analysis

### Design Philosophy

The application is built around a **local-first, graph-centric information architecture**. Several principles emerge directly from the code:

**Capture-first, organize-later.** The `Cmd+I` hotkey path is the most direct, automated flow in the codebase — frontmost app detection, URI extraction, deduplication, and system tag inference all happen without user input. Organization is deferred; captured objects land in existence and are sorted out through tagging and containers after the fact.

**Containers as queries, not folders.** The `evaluateContainer` logic reveals that spaces are not buckets — they are set expressions: `(query_results ∪ explicit_contains) − excludes`. An object can satisfy a container's query without the user ever placing it there. This is a fundamental stance against hierarchical organization.

**Incremental reactivity over state reloads.** LIVE SELECT subscriptions (six of them, covering all tables and edges) push diffs to the renderer. The store applies `CREATE/UPDATE/DELETE` actions incrementally. The design rejects polling or full-reload approaches.

**Mutation-safe persistence.** Every DB write calls `scheduleExport(db)` — a 5-second debounced JSON export. Data lives in SurrealDB for speed; JSON lives on disk for durability. Two representations, neither redundant.

---

### System Architecture

**Process topology:** Electron with two BrowserWindow instances.
- `main` — full application window
- `overlay` — 520×520 `QuickSpaceView`, toggled by `Cmd+\``
- Both windows share a single SurrealDB process (`surreal start` spawned as a child process at `~/.index/surreal/`)

**Communication model:**
- Renderer → Main: `ipcRenderer.invoke()` (request/response, async)
- Main → Renderer: `webContents.send()` (event stream, live updates)
- Active space is reported renderer → main to allow capture to target the correct container

**Database schema (SurrealDB, schemaless but structured):**
- `objects` — leaf items and containers (distinguished by presence of `query` field)
- `tag_definitions` — user and system tag records
- `tag_types` — system type registry (medium, kind, file, origin) with display/editability flags
- Edge tables: `tagged`, `contains`, `excludes`, `typed` — all first-class `RELATE` edges, not join tables

**Export layer:** `~/.index/export/` contains one JSON file per object and tag, written on a debounce timer. App quit triggers an immediate flush.

**Migration:** First v0.4 boot reads v0.3 JSON at `~/.index/objects/`, imports to SurrealDB, writes `~/.index/.version` to mark complete.

---

### Code Implementation

**Main process** (`electron/main/`) is organized cleanly by concern:

- `db/connection.js` — spawns SurrealDB, defines tables and seeds `objects:root` + `objects:all`
- `db/live-queries.js` — one LIVE SELECT per table/edge, broadcasts to all windows
- `db/export.js` — debounced async JSON writer
- `db/services/object-service.js` — `createObjectCore()` + system tag inference from sources
- `db/services/container-service.js` — `evaluateContainer()` set logic
- `domain/tag-types.js` — authoritative registry for system tag types; IPC handlers enforce it
- `utils/normalize.js` — flattens SurrealDB `RecordId` objects to strings at the IPC boundary
- `ipc/db-handlers.js` — all CRUD and query handlers; calls `scheduleExport()` on every mutation
- `capture/index.js` — OSA-script-based frontmost app detection, app-specific context handlers

**Frontend** (`src/`) uses a single Zustand store (`useIndexStore`) with:
- Flat state: `objects`, `tags`, `tagTypes`, `typedEdges`, `objectTags` cache
- Browser-style nav: `navHistory[]`, `navCursor` for back/forward
- Live subscriptions wired in `subscribeToLive()`, called once on mount
- Derived state methods compute on access: `getDisplayObjects()`, `getDatesWithObjects()`, `getAllContainers()`

**Views:**
- `ObjectListView` — finder-style list with multi-select and keyboard navigation
- `CalendarView` — objects grouped by `created_at` date
- `GraphView` — D3 force-directed graph, nodes are objects, edges are relationships
- `SpacesView` — card grid of containers with drag-to-reorder
- `CreateSpaceModal` — three-column drag-and-drop tag query builder (all / any / none)
- `QuickSpaceView` — overlay window combining command palette + graph

**Notable implementation details:**
- System tags are not string fields on objects — they are proper tag records linked via `typed` edges to `tag_types`, making them queryable the same way user tags are
- `RepairMissingSystemTags` IPC handler exists for backward compatibility with objects captured before the type system was fully wired
- `container-service.js` fetches full records for the final membership set — evaluation returns hydrated objects, not just IDs
- Keyboard shortcuts centralized in `useKeyboardShortcuts.js`, covering navigation, command palette, and settings without conflicts
