## Key Decisions

- **`toString()` over `.id.id`**: `record.id?.toString?.()` produces `"table:localId"` natively from SurrealDB RecordId objects, making IDs self-describing throughout the stack and removing the need for table-prefix construction at query sites.
- **Normalization in `live-queries.js`**: The root cause of ID leakage into the store was that LIVE SELECT events bypassed `normalizeRecord()`. Fixing it there — rather than adding defensive code in the store — closes the gap at the correct layer.
- **`db/services/` subdirectory**: Groups service-layer modules (object and tag operations) separately from infrastructure modules (connection, export, live-queries, migration, repair), making the db layer easier to navigate.
- **`windows/` → `dialogs/`**: The directory contained only a dialog; the prior name implied a window-management concern that wasn't there.
- **Data wipe on ID format change**: Mixed-format data in SurrealDB would require a migration script of non-trivial complexity for a pre-release codebase. Clean wipe was the correct trade-off.
