# Development Log — 2026-03-18

## v0.5: Audit and Unification

v0.5 is a housekeeping version. No new features were added. The goal: make the codebase
accurately describe itself and eliminate the accumulated conceptual drift from v0.4

## Session 001 — Codebase Audit and Comment Policy

### Starting State

The workspace opened cold. `ORIENT.md` was a blank template — no prior session record
existed. The first act was a deep study of the codebase followed by comparison against
v0.4 docs to correct misconceptions from stale code comments.

### Corrections Made to Prior Understanding

Several patterns in the code commented on things that had changed during v0.4 development
without updating those comments. Key corrections established at the top of the session:

**Undo system is real.** Comments and code structure suggested it was archived or removed.
In fact, `useHistoryStore` and `UndoToast` were implemented and wired. (They are now in
`_archive/` in v0.5, deferred for re-wiring with the object detail view.)

**`medium` and `kind` are not a contradiction.** `medium` is signal format (audio/video/
image/text); `kind` is semantic form (book/essay/song/photo). Both are correctly defined
in the domain registry. `medium` auto-assignment at capture time is simply not yet
implemented — a backlog item, not a design flaw.

**Command palette is more functional than comments suggested.** Space navigation (all
spaces as targets) was working; comments described it as "sparse."

**The rename history matters.** v0.4 passed through `collections` → `spaces` (as a
separate DB table) → spaces folded into `objects` with `container: true`. Stale comments
in several files still referenced intermediate states (`space_objects`, `evaluateSpace` as
a prior pattern, `persistToIndex`). These were the primary source of confusion.

### Work Executed

**Comment audit across all source files.** Stale version-changelog headers removed:
```
// Changes from v0.3:
//   - tag_assignments replaced by RELATE edges
//   - spaces table removed
```
These are git history, not code documentation. Each file's header was rewritten to
describe the current state.

Files updated: `connection.js`, `live-queries.js`, `object-service.js`, `system-tags.js`,
`db-handlers.js`, `index.js` (main), `store/index.js`, `preload/index.js`, `export.js`,
`migration.js`, `domain/tag-types.js`, `metadata-extractor.js`, `App.jsx`.

**Comment policy established.** `docs/COMMENT-CONVENTION.md` written: comments describe
what the code *is*, not what it *was*. Version changelog information belongs in commit
messages and session logs, not in source files.

**Docs written for v0.5.** `ABOUT.md`, `GLOSSARY.md`, `BACKLOG.md`, `PROJECT_DESIGN.md`,
`QUICKSTART.md` — all updated or authored fresh to reflect v0.5 starting state.

## Session 002 — Terminology Unification: "container" → "space"

### The Contradiction

During the v0.4 development cycle, two terms had accumulated for the same concept:

| Layer | Term used |
|---|---|
| DB field | `container: true` |
| Service | `container-service.js`, `evaluateContainer()` |
| IPC channels | `db:createContainer`, `db:updateContainer`, `db:evaluateContainer` |
| Store constants | `ROOT_CONTAINER_ID`, `ALL_CONTAINER_ID` |
| Store actions | `createContainer()`, `getAllContainers()`, `reorderContainers()` |
| UI/store state | `activeSpaceId`, `enterSpace`, `spaceObjects` |
| Components | `CreateSpaceModal`, `QuickSpaceView` |

The split had emerged naturally: "space" appeared in the UI before the data model
crystallized. By v0.4.2, the correct term was "space" everywhere — but the data layer
hadn't been renamed.

The user resolved it explicitly: **"space" is the single correct term at all layers.**

### Executed

**Dead code deleted:**
- `src/components/CreateContainerModal.jsx`
- `src/components/CreateContainerModal.css`
- `src/components/QuickContainerView.jsx`

These were never imported anywhere in the v0.5 codebase.

**`container-service.js` → `space-service.js`:**
`evaluateContainer(db, containerId)` → `evaluateSpace(db, spaceId)`. All locals, SQL
conditions, and the file header updated.

**`connection.js`:**
- `ROOT_CONTAINER_ID` → `ROOT_SPACE_ID`
- `ALL_CONTAINER_ID` → `ALL_SPACE_ID`
- `seedSystemContainers()` → `seedSystemSpaces()`
- Seeded records: `container: true` → `space: true`
- Idempotent startup migration added:
  ```sql
  UPDATE objects SET space = true UNSET container WHERE container = true
  ```
  Runs on every boot; is a no-op once existing data is migrated.

**`db-handlers.js`:**
IPC channels `db:createContainer`, `db:updateContainer`, `db:evaluateContainer` renamed
to `db:createSpace`, `db:updateSpace`, `db:evaluateSpace`. Import updated.

**`preload/index.js`:** API surface renamed to match.

**`object-service.js`:** Field references `objectData.container` → `objectData.space`.

**`store/index.js`:** All action names (`createContainer` → `createSpace`, etc.), all
field filters (`o.container` → `o.space`), store constants, local variables, and comments.

**`App.jsx`, `ObjectListView.jsx`, `AddressBar.jsx`, `CreateSpaceModal.jsx`:** Props,
field access, comments.

**All five docs:** Remaining "container" domain references updated.

### Bug Discovered and Fixed

During the final audit, a live CSS rendering bug was found:

`ObjectListView.jsx` was emitting class `is-space` on space rows (correctly renamed).
`ObjectListView.css` still had selectors on `.object-row.is-container`. The selectors
never matched. Space rows had been unstyled — no bold name, no purple accent, no hover
state — since the JSX rename.

Fixed: CSS selectors updated to `.object-row.is-space`.

### Follow-on Rename

`spaceObjects` → `activeSpaceObjects` (store field, all consumers, docs). More precise:
`spaceObjects` was ambiguous given other space-related state keys; `activeSpaceObjects`
makes the lifecycle relationship explicit.

### What Was Not Changed

- `contains` and `excludes` edge table names — semantically neutral relational verbs;
  no domain-term problem; migration cost with no benefit
- `objects:root` and `objects:all` record IDs — no "container" in these strings
- `activeSpaceId`, `enterSpace`, `exitSpace`, `toggleSpace`, `_activateSpace` — already
  correct
- `CreateSpaceModal`, `QuickSpaceView` component names — already correct
- `SettingsView.jsx` references to macOS "Spaces" (the OS feature) — unrelated

## Open Contradictions Carried Forward

1. **Object detail view is absent.** `onObjectOpen` fires on double-click of a leaf;
   App.jsx ignores it. No read/edit surface exists for individual objects.
2. **Graph is nodes-only.** The data model is graph-first; the view renders labeled
   circles with no edges.
3. **`medium` auto-assignment is dormant.** Tag type is defined; no capture handler
   derives or applies it.
4. **Undo is archived.** `useHistoryStore` + `UndoToast` built and complete; not wired
   to the current UI.
5. **Capture is Safari-only in practice.** `defaultHandler` fires for other browsers but
   produces nothing.
