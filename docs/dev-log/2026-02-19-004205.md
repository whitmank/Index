## Key Decisions

- **Repair at initialization, not on demand**: Previously, system tags were repaired when the frontend first requested them. Moving repair to `startDatabase()` ensures every object has correct system tags before any UI interaction, eliminating transient "missing tag" states.
- **Repair is non-critical**: The repair function catches its own errors and does not re-throw. A repair failure logs a warning but does not block database startup or app launch.
- **URLs without extensions get `"url"` extension tag**: Rather than leaving URL-sourced objects with a null `file_extension` tag, returning `"url"` gives every object a meaningful value and enables filtering by source type.
- **Tag value casing preserved**: `toTitleCase()` was converting `pdf` → `Pdf`, `jpg` → `Jpg`, which was inconsistent with how these values are stored and compared. Removing it makes display match the canonical stored value.
- **System tag structure is never fully removed**: The × button on a system tag calls a null-value assignment path, not a delete path. This preserves the invariant that every object always has both `media_type` and `file_extension` slots.

## Technical Notes

- `repairObjectSystemTags` queries `tag_assignments` then fetches the referenced `tag_definitions` to determine which system tag types are already present. It only creates assignments for missing types.
- `findOrCreateSystemTag` in `repair.js` is a local copy scoped to the repair module; it is separate from the version in `ipc/db-handlers.js`. If the tag creation logic diverges in future, both copies will need updating.
- The repair loop is sequential (not parallelized) to avoid overwhelming the SurrealDB in-process connection with concurrent writes during startup.
- `!important` on tag text color rules is intentional: some parent component styles were overriding the color. The `!important` declarations are scoped tightly to tag-specific selectors and should not affect other components.
- `extractMediaType()` for URLs without extensions falls through to the `default` case and returns `"other"`. This was not changed this session; only `extractFileExtension()` was updated.
