# Development Log - 2026-02-23

## Session Summary

Identified and fixed a critical UI stability bug where `ObjectDetailSidebar` was unmounting and remounting on every data reload, causing visual flicker and disrupting user navigation. The root cause was a loading state that treated routine data updates the same as initial app load. The fix distinguishes between these two conditions, preserving the established UI during reloads.

## Key Decisions

- **Preserve UI through data reloads, not just on selection**: Once the sidebar is open, data updates should refresh its content in-place rather than cycling it through unmount/remount. Avoids CSS transition side effects.
- **`cachedObjectRef` over conditional rendering**: Using a ref to hold the last valid object lets the sidebar render stale-but-correct data during the brief window when the store is reloading, without introducing complex state synchronization.
- **`normalizeId` extracted as a helper**: SurrealDB returns IDs in two formats depending on context. Centralizing normalization prevents future inconsistencies rather than leaving ad-hoc `object.id.id || object.id` expressions scattered through the code.
- **Loading state has two distinct semantics**: "No data yet" (show spinner) vs "refreshing existing data" (keep UI visible). The original code conflated these, causing unnecessary full-tree unmounts during routine operations.

## Technical Notes

- Root cause chain: file watcher fires → `loadObjects()` called → `loading = true` → App renders loading `<div>` instead of fragment → sidebar unmounts (CSS slide-out) → loading finishes → sidebar remounts (CSS slide-in)
- The `key={`sidebar-${normalizeId(selectedNodeId)}`}` prop intentionally forces a remount only when the selected object actually changes, not during reloads of the same object
- SurrealDB ID normalization: IDs may arrive as plain strings or as `{id: "value"}` objects depending on which IPC path returns them; `normalizeId` handles both cases
- Tested scenarios post-fix: open sidebar, add/delete sources, add/delete tags, file watcher reload, close via X/Escape, delete selected object — all stable
