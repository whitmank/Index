## Key Design Decisions

### 1. Sidebar vs. Modal Pattern
**Decision:** Implemented a right-edge slide-in sidebar rather than a centered modal.
**Rationale:** Sidebars allow users to maintain context with the graph while viewing details. The slide-in animation provides smooth visual feedback, and the backdrop preserves click-to-close functionality of modals.

### 2. Cmd+Click for Direct Source Opening
**Decision:** Added modifier key detection to bypass sidebar when Cmd is held during click.
**Rationale:** Power users often want quick access to source files without the sidebar UI. This follows macOS conventions where Cmd modifies click behavior (e.g., Cmd+Click for new tab in browsers).

### 3. Click-to-Edit Title Pattern
**Decision:** Made title directly editable by clicking, rather than requiring a separate "Edit" button.
**Rationale:** Reduces UI clutter and provides a more direct manipulation interface. Hover state indicates interactivity, and auto-focus/select provides smooth editing experience.

### 4. Panel Window Type with Always-On-Top
**Decision:** Used `type: 'panel'` with `alwaysOnTop: true` instead of regular window or dock integration.
**Rationale:** Creates a persistent, non-intrusive overlay that users can toggle with `Cmd+\``. Hiding from dock and Cmd+Tab cycle prevents the window from cluttering the application switcher, while `canJoinAllSpaces` keeps it accessible across virtual desktops.

### 5. Sharp Corners vs. Rounded
**Decision:** Set `roundedCorners: false` for sharp window edges.
**Rationale:** Sharp corners align with the angular corner decoration design language. Rounded corners conflicted with the 45-degree triangle SVG elements and rectangular frame border.

### 6. SVG Corner Decorations
**Decision:** Implemented 45-degree angular triangles at corners using SVG paths rather than CSS or images.
**Rationale:** SVG provides crisp rendering at any scale, allows precise control over gradient fills and strokes, and integrates seamlessly with the D3 graph rendering pipeline. Angular design adds visual interest and frames the graph viewport.

### 7. Dark Node Circles with Light Background
**Decision:** Used dark fills (`#333333`) for nodes against a light gradient background.
**Rationale:** Provides strong contrast for readability, matches modern design trends toward subtle backgrounds with prominent interactive elements. Drop shadows on hover/select add depth without overwhelming the minimalist aesthetic.

## Technical Implementation Details

### Force Simulation Integration
The node selection system integrates with the existing D3 force simulation:
```javascript
nodeGroup
  .on('click', (event, d) => {
    if (event.metaKey || event.ctrlKey) {
      window.electronAPI?.openSource?.(d.source);
    } else {
      onNodeClick(d.id);
    }
  })
  .classed('selected', d => d.id === selectedNodeId);
```

### Closing Animation Coordination
Implemented two-phase closing to ensure animations complete before unmounting:
```javascript
const handleClose = () => {
  setIsClosing(true);
  setTimeout(onClose, 300); // Match animation duration
};
```

### SVG Corner Triangle Geometry
45-degree triangles created with precise path calculations:
```javascript
const cornerSize = 32;
const trianglePath = `M 0 0 L ${cornerSize} 0 L 0 ${cornerSize} Z`;
```
Applied to all four corners with appropriate transforms (rotation, translation).

### IPC for Source Opening
Electron IPC channel enables web renderer to open files via main process:
```javascript
// Preload
openSource: (source) => ipcRenderer.send('open-source', source)

// Main process
ipcMain.on('open-source', (event, sourcePath) => {
  shell.openPath(sourcePath);
});
```

### Platform-Specific Window Manager Pattern
Factory pattern enables clean platform-specific implementations:
```javascript
export default class WindowManagerFactory {
  constructor() {
    if (process.platform === 'darwin') {
      return new MacOSWindowManager();
    }
    return new GenericWindowManager();
  }
}
```

## Technical Notes

### macOS Panel Window Behavior
The `type: 'panel'` window type provides utility panel semantics on macOS but requires careful configuration:
- Defaults to floating above normal windows (desired)
- Can be hidden from dock with `collectionBehavior: ['ignoresCycle']`
- `canJoinAllSpaces` makes it available on all virtual desktops
- `roundedCorners: false` necessary for custom corner decorations

### SVG in React with D3
When mixing SVG manipulation between React and D3, the SVG root must be managed by D3 (using `useRef` and `select()`). React can provide the initial `<svg>` element, but D3 takes full control via imperative updates to avoid reconciliation conflicts.

### CSS Animation Timing
All animations use 300ms duration with `ease` timing function for consistency:
- Sidebar slide: `slideInRight`/`slideOutRight`
- Backdrop fade: `fadeIn`/`fadeOut`
- Hover transitions: 200ms for more responsive feel

### Drop Shadow Performance
Using CSS `filter: drop-shadow()` on hover can impact performance with many nodes. Currently acceptable for expected graph sizes (dozens of nodes), but may need optimization for hundreds of nodes (e.g., only apply shadow to hovered node, not via CSS class).

### File Opening Cross-Platform
`shell.openPath()` works across platforms (macOS, Windows, Linux) to open files with default application. Returns a promise that resolves to an error string if the path doesn't exist or can't be opened.
