# Development Log - 2026-03-11

## Session Summary

Rebuilt the Index application from v0.3 to v0.4 following the architecture spec at `../feature-dev/ARCHITECTURE_v0.4.md`. The migration replaced ephemeral SurrealDB with a persistent store, introduced LIVE SELECT for reactive state, consolidated three Zustand stores into one, and added a partial undo system. 54 files were created, rewritten, or deleted across 7 phases.

## Activities Completed

- **Phase 0 — Persistent SurrealDB**: Switched SurrealDB data directory from a temp dir to `~/.index/surreal/`. Wrote `electron/main/db/migration.js` to import v0.3 JSON data on first boot. Removed startup hydration (no longer needed).
- **Phase 1 — LIVE SELECT**: Wrote `electron/main/db/live-queries.js` to subscribe to `objects`, `tag_assignments`, and `collections` tables and push diffs to the renderer via IPC. Updated preload to expose `onObjectsLive`, `onTagAssignmentsLive`, `onCollectionsLive`.
- **Phase 2 — Remove Full Reloads**: All mutation handlers now call `scheduleExport(db)` instead of `await persistToIndex(db)`. Stores no longer call `loadObjects()` after mutations; LIVE SELECT patches state instead.
- **Phase 3 — Async Export**: Wrote `electron/main/db/export.js` with a debounced 5s export to `~/.index/export/`. `exportToJson()` is called on `before-quit` for a clean exit snapshot. Retired `watchers/objects.js`.
- **Phase 4 — ID Normalization**: Wrote `electron/main/utils/normalize.js` with `normalizeRecord()` / `normalizeRecords()`. Applied at the IPC boundary in all handlers, eliminating the `id?.id || id` pattern from frontend code.
- **Phase 5 — Domain Centralization**: Wrote `electron/main/domain/tag-types.js` as a system tag type registry with display/editable/deletable/order metadata. Exposed `db:getTagTypes` IPC handler. Deletion guard for system tag types moved to handler level. `TagAssignmentSection.jsx` now reads `tagTypes` from store.
- **Phase 6 — Store Consolidation**: Wrote `src/store/index.js` (`useIndexStore`) merging objects, collections, tags, tagTypes, and objectTags. `subscribeToLive()` wired in `App.jsx` on mount. Migrated all component imports. Deleted `store/objects.js`, `store/collections.js`, `store/tags.js`. Wired `CollectionsSidebar` into `App.jsx` (existed in v0.3 but was never rendered).
- **Phase 7 — Undo System (partial)**: Wrote `UndoToast.jsx` and `UndoToast.css` for a 4s transient notification after destructive actions. Delete-object undo uses LIVE SELECT for state recovery. History store left unchanged.

## Key Decisions

- **Persistent SurrealDB over ephemeral**: Enables LIVE SELECT and eliminates the need to reload full state after every mutation. Migration script handles the one-time transition from v0.3 JSON.
- **Single unified store**: Merging three stores removes cross-store sync bugs and simplifies component imports. `history.js` stays separate because its concerns (undo stack) are orthogonal to live data.
- **Normalization at IPC boundary**: Keeps `id?.id || id` handling in one place rather than scattered across frontend components.
- **Deletion guard at handler level**: System tag type protection belongs in the backend, not the UI, so it cannot be bypassed by future frontend changes.
- **Debounced export over synchronous persist**: Reduces write amplification on rapid mutations; `before-quit` flush ensures no data loss on exit.

## In Progress / Next Steps

- **Undo coverage is partial**: Only delete-object and some tag operations are wired. Remaining destructive actions (collection delete, bulk operations) need undo closures added to their handlers.
- **History store integration**: `store/history.js` was left unchanged; it should be reviewed for compatibility with the LIVE SELECT state model.
- **Test the migration path**: The v0.3 → v0.4 migration script (`migration.js`) should be exercised against a real v0.3 data directory to verify correctness before shipping.
- **CollectionsSidebar**: Now rendered for the first time (was dead code in v0.3). Needs QA pass to confirm behavior is correct in the new store model.

## Blockers / Open Questions

- The undo system for non-delete mutations is undefined. Decide whether to extend `history.js` or adopt a different pattern before adding more undo coverage.
- Confirm the debounce interval (5s) is acceptable for the expected mutation rate; adjust in `export.js` if needed.

## Technical Notes

- SurrealDB data lives at `~/.index/surreal/`; exports land at `~/.index/export/`.
- Migration runs once on first boot (guarded by a flag); subsequent boots skip it.
- LIVE SELECT diffs arrive as IPC events — components must not assume full-object payloads; they receive only changed fields.
