## Session 007 — Icon System and List View Refinement

### Work

The session's entry point was a request to add a type filter button to the empty
top-left corner of the list header. The implementation exposed a deeper design problem:
icons were ad hoc, per-component, and not shareable.

**`src/icons/index.jsx` established as the canonical icon module.**
Three exports: `ObjectIcon` (solid dot), `SpaceIcon` (hollow ring), `MonadIcon` (ring +
dot). All share `viewBox="0 0 4 4"`, center `(2,2)`, inner dot `r=1`, outer ring `r=φ`
(1.618, golden ratio), `vectorEffect="non-scaling-stroke"` on all ring elements.
Default render size `size=12`. This is the single source of geometry for all ●/○
language in the application.

**`FilterIcon` delegates to shared icons.**
The filter button in the list header is no longer self-contained. `FilterIcon` accepts
`side` (`'objects'|'spaces'`) and `combined` (bool), maps the combination to the right
icon export, and renders it. Row type badges (`ObjectIcon`, `SpaceIcon`) import from the
same module. Column-level flex centering is now the single alignment rule for both header
and rows — the old `margin: auto` / `text-align: center` split is gone.

**Two-bit filter state model.**
The original three-state cycle (`all → objects → spaces`) relied on a `preAllFilter` ref
to remember state before entering combined view. Replaced with `filterSide`
(`'objects'|'spaces'`) and `filterCombined` (bool) as independent state variables.
Single click: exits combined if active, else toggles side. Hold (300 ms): toggles
combined. No ref needed. The displayed icon derives from the combination of both values.

**View toggle and `V` shortcut.**
The AddressBar's two side-by-side list/graph buttons were collapsed to one, displaying
the current view's icon and toggling on click. Keyboard shortcut `V` (no modifier,
guarded against input targets) wired through `useKeyboardShortcuts.js` and `App.jsx`.

**Minor list view polish.**
URI removed from list rows (name only). Alternating row tint added at `rgba(0,0,0,0.025)`.

## Session 008 — Tag System Repair

### The Bug

The user reported: creating a tag typed "Author" with value "Andy Weir" produced a
single typeless tag named "Author: Andy Weir". Tracing the failure revealed two
independent structural breaks.

**Break 1 — `TagAssignmentSection` indexed an array by string key.**
`tagTypes` in the store is an array. `tagTypes[tag.type]` — indexing by string — always
returns `undefined`. The component had diverged from the correct pattern used in `TagsView`,
which resolves type via the `typedEdges` edge table.

**Break 2 — `db:createTag` silently dropped the type.**
The IPC handler accepted `name`, `color`, `description`, `system`, and `created_at` only.
A `type` string sent from the form was never read; no `typed` edge was ever created.

### Fixes

**`TagAssignmentSection` rewritten to use `typedEdges`.**
Tag type is now resolved via `typedEdges.find(e => e.in === tagId)?.out` — identical to
the `TagsView` pattern. `createTag` calls now pass `typeId` (a record ID), not a type
name string.

**`TagAddInput` — flexible single/two-field form.**
A new `TagAddInput` sub-component replaces the broken creation form. Single field acts
as value entry with autocomplete showing existing tags (displayed as `Type · name`).
Pressing Tab retroactively promotes field 1 to TYPE and introduces field 2 as VALUE.
Three cases handled without the user declaring intent upfront:
- Existing type + existing value → autocomplete, assign on Enter
- Existing typed tag, single exact match → auto-assigns without Tab
- Tab pressed → creates typed tag; auto-creates type if it doesn't exist

Cognitive field order is now type → value, matching English. Deduplication enforced.

## Session 009 — GraphView: Interaction and Simulation Architecture

### Thread 1 — Click-to-Select and Visual Language

`GraphView` was extended to match the interaction model and visual language of the list view.

**●/○ visual language.** Nodes carry the `isSpace` flag from the objects array. Spaces
render as hollow rings (`.node--space`: `fill: none`, stroke-based); leaf objects as
filled circles. Applied in `GraphView.jsx` and `GraphView.css`, with hover and selected
variants.

**Click-to-select.** `App.jsx` wraps the graph in `content-with-detail`, threading
`onObjectSelect` to `GraphView` and rendering `ObjectDetailPane` alongside — the same
layout as the list view. Single-click selects; cmd+click opens source URI externally.
`selectedId` state and a dedicated effect sync the `.selected` CSS class without touching
the simulation. `onObjectSelect` is stored in a ref (`onObjectSelectRef`) so the click
handler reads it at call time — the parent re-rendering (producing a new function
reference) does not trigger simulation rebuild.

### Thread 2 — Simulation Lifecycle Refactor

The core open contradiction: any change to `objects` (a name edit, a LIVE SELECT push)
caused React to re-run the monolithic `useEffect`, which fired `stopSimulation`, wiped
the SVG with `svg.selectAll('*').remove()`, and rebuilt from scratch with randomized
positions. All position state was lost on every update.

The structural cause: D3's simulation is a stateful mutable object; React treats `objects`
as an immutable prop; a single effect keyed on `objects` guaranteed full teardown on any
data change.

**Resolution — three independent effects.**

- **Mount effect** (`[]`) — creates SVG skeleton, `<g class="graph-inner">`, and zoom
  behavior once. Never tears down. Zoom and pan state survive all data updates.
- **Data effect** (`[objects]`) — D3 general update. Builds a position map from current
  nodes before replacing them. Survivors carry `x`, `y`, `vx`, `vy`, `fx`, `fy` forward.
  Calls `simulation.nodes(newNodes)` then `simulation.alpha(0.3).restart()` for gentle
  resettlement. Enter/update/exit applied to DOM and labels updated in-place.
- **Resize effect** (`[dimensions]`) — updates `dimensionsRef` and nudges `forceCenter`
  at alpha 0.15 only.

**`createForceSimulation` API changed.**
`forceSimulation.js` rewritten. `createForceSimulation` now takes
`(getNodes, dimensions, onTick)` — a `getNodes` accessor function rather than a static
array. The tick's boundary-constraint loop calls `getNodes()` on every tick, ensuring it
reads the live node array after `simulation.nodes()` replaces it. New exports:
`updateSimulationNodes` and `updateSimulationDimensions` for the data and resize paths.

## Session 010 — Polish, Persistence, Space Rules, and Device Infrastructure

Session 010 moved on two scales: tight UI corrections in the first half, and a
foundational schema extension in the second.

### First Half — UI Corrections and Persistence

**Settings Escape restores previous context.**
The initial implementation called `setActiveTopLevelView('spaces')` unconditionally.
`App.jsx` now captures a `settingsReturnTarget` ref — `{ view, spaceId }` — at the
moment `navigateTo('settings')` is called. The Escape handler reads the ref and calls
`setActiveTopLevelView(view)` + `enterSpace(spaceId)` to restore the exact prior state.

**Backtick filter toggle.**
`` ` `` was unbound. Added to `ObjectListView`: tap cycles `filterSide`, hold (300 ms)
toggles `filterCombined` — parity with the mouse hold behavior. Both the main and
empty-state containers handle `onKeyUp`.

**Keybinds tab in Settings.**
A fifth tab added to `SettingsView.jsx` / `SettingsView.css`. Three groups: Navigation,
List View, Settings. Each row shows description and styled `<kbd>` keys with "or"
separators. Static documentation; source of truth remains `useKeyboardShortcuts.js`.

**Filter/sort state persisted per space.**
`filterSide`, `filterCombined`, `sortField`, `sortDir` removed from `ObjectListView`
component state. `App.jsx` maintains `spacePrefsRef` — a map keyed by `activeSpaceId` —
initialized from and written back to `localStorage['index:space-prefs']`. `ObjectListView`
receives current prefs as props and calls `onPrefsChange` on change. State survives view
toggles, space navigation, and app restarts.

### Second Half — Space Rules and Device Infrastructure

**`SpaceRulesSection` — inline rule editor.**
`src/components/SpaceRulesSection.jsx` + `SpaceRulesSection.css`. Replaces the orphaned
`CreateSpaceModal` edit path. Three tag rule groups — All of / Any of / None of — each
with colored pills (green / blue / red), × to remove, `+` to open an inline autocomplete
input (keyboard-navigable: ↑↓ Enter Escape). Calls `updateSpace` on each add/remove;
LIVE SELECT propagates the result. Null-named system tag placeholders filtered from
suggestion pool to prevent a `null.toLowerCase()` crash.

**Object detail pane simplified.**
INFORMATION section header removed. Modified date removed. Single "Added / date" row
added above Sources. Source display changed from monospace URI to `source.origin` badge
(full URI retained in `title` for hover access).

**Devices lifted to first-class records.**
`source.origin` had been a plain embedded string — not relational, not queryable, not
able to carry its own properties. Device-to-device file transfer (explicitly named as a
future goal) required real identity. Full implementation across 10 files:

| File | Change |
|---|---|
| `connection.js` | `devices` table added to schema; `devices:⟨web⟩` seeded at boot; boot-time backfill migrates `source.origin` strings to `sourced_from` edges |
| `device-service.js` (new) | `getOrCreateDevice(name)`, `getDevices()`, `setSourcedFromEdges(objectId, origins)` |
| `object-service.js` | `setSourcedFromEdges()` called on object create and source update |
| `db-handlers.js` | `db:getDevices` IPC handler added; device rules threaded through `evaluateSpace` |
| `space-service.js` | `evaluateSpace()` extended: `from_any` and `from_none` device rule arrays; queries `sourced_from` edges when rules are present |
| `live-queries.js` | `sourced_from` changes added to LIVE SELECT coverage |
| `preload/index.js` | `getDevices` and `onDevicesChanged` exposed on `window.electronAPI` |
| `store/index.js` | `devices` state added; loaded at boot; live-updated via channel |
| `SpaceRulesSection.jsx/.css` | From any / Not from device groups with purple/sienna pills and `RuleDeviceInput` autocomplete |

## State at End of Sessions 007–010

The application has a coherent interaction layer at both list and graph views. The ●/○
visual language is consistent across all views and backed by a principled shared icon
module. The tag system is structurally correct end-to-end. The graph is live — data
changes propagate in-place without position loss. Space rules are inline-editable
directly in the detail pane. Origins are relational: `sourced_from` edges connect objects
to first-class device records, and space rules can filter on them.

## Open Contradictions Carried Forward

1. **Graph renders nodes only.** `contains`, `tagged`, and `sourced_from` edges are live
   and complete in the data model. `GraphView` does not render any of them.

2. **No full-screen object view.** The detail sidebar exists. Double-click opens source
   URI externally. No dedicated in-app view for a single object at full focus.

3. **`medium` auto-assignment is dormant.** Tag type is seeded and registered; never
   applied at capture time.

4. **Undo is in archive.** `useHistoryStore` and `UndoToast` are complete and unwired.
   Destructive actions — delete, unpin — are irreversible.

5. **Capture is Safari-only in practice.** `defaultHandler` fires for other apps but
   produces no output.

6. **`CreateSpaceModal` is fully orphaned.** The inline create flow and `SpaceRulesSection`
   together replace everything it did. The component remains in the codebase unmounted.

7. **Stale `.space-rules` CSS in `ObjectDetailPane.css`.** Those selectors are no longer
   used now that `SpaceRulesSection` owns the rules display.
