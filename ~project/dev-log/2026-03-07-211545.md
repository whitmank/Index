# Development Log - 2026-03-07

## Session Summary

Implemented the Global Cmd+I Capture feature (Safari Flow) for the Index desktop app. The system-wide hotkey captures the current browser context into Index — detecting the active Safari URL, fetching OG metadata, creating a new object (or surfacing the existing one on duplicate), then focusing the Index window with that object selected in the sidebar. The architecture is deliberately extensible so additional app handlers (Chrome, Finder, Spotify, etc.) can slot in as new files with no changes to the core flow.

## Key Decisions

- **Extensible handler interface** (`canHandle(appName): boolean`, `capture(): Promise<CaptureResult|null>`): New app contexts (Chrome, Finder) are added as new files with no modification to the routing core. Open/closed principle applied at the file level.
- **CaptureResult shape** (`{ name, uri, mediaTypeHint }`): Minimal contract between handlers and the creation layer; keeps handlers decoupled from DB internals.
- **og:type passed verbatim as `mediaTypeHint`**: Values like `video.other`, `article`, `music.song` become the `media_type` tag as-is; `website` used as fallback. Decision favors publisher intent over lossy normalization to an internal vocabulary — easier to remap later than to recover lost signal.
- **osascript called before `mainWindow.focus()`**: Frontmost app detection must happen before Electron steals focus. If detection ran after the window was raised, the result would always be "Electron". This sequencing is load-bearing for correct handler routing.
- **OG fetch reads only up to `</head>` with a 64 KB cap**: Avoids downloading full pages for metadata. Browser-like User-Agent reduces bot blocking. 8-second timeout via `AbortSignal.timeout`. Fetch failure is non-fatal — falls back to AppleScript page title.
- **Duplicate detection via `findObjectByUri`**: Scans all objects' sources arrays for a URI match before creating. On duplicate: focus existing object, skip creation. Prevents clutter and data loss without requiring a separate index.
- **Renderer selection via `objects:selectObject` IPC event**: Main process sends the new object's ID after focusing the window. App.jsx sets `selectedNodeId`, opening the sidebar immediately. The graph view catches up independently via the file watcher — no blocking wait for store sync.

## Technical Notes

- The osascript timing constraint (detect before focus) is a subtle but critical sequencing requirement. Any future changes to the capture flow that alter window focus order must preserve this.
- `object-service.js` is now the canonical location for programmatic object creation. The IPC handler in `db-handlers.js` is a thin wrapper and should stay that way — avoids logic duplication when capture or future automation paths create objects outside of user-initiated IPC calls.
- OG metadata `og:type` vocabulary is publisher-defined and not normalized. Downstream tag display and filtering should be tolerant of arbitrary string values in `media_type`.
- The handler pattern assumes `appName` from AppleScript (e.g., `"Safari"`, `"Google Chrome"`). Verify exact process names when adding Chrome or other handlers.
